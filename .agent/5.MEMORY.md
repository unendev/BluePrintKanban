# 智慧沉淀

## 为何从列式改为画布式？
用户最初的愿景是 "UE 蓝图" —— 自由节点、连线、网格。第一次实现误做成了 "带计时器的三列看板"，虽然功能可用但偏离了核心灵感。第二次重构直接拥抱蓝图隐喻：无限画布、自由定位、节点连线。

## 技术决策 Why
- **纯 localStorage**: 用户要求 "完全脱离云"，所以所有数据模型必须自包含在 JSON 中
- **SVG 连线而非 HTML div**: SVG path 的贝塞尔曲线是蓝图风格的核心视觉元素，用 div 伪元素无法实现平滑曲线
- **camera 按项目隔离**: 不同项目的画布布局完全不同，共享一个 camera 会导致切换时迷失位置

## 已知坑
- 旧文件 (TaskChartDialog.tsx, useTimerControl.ts) 包含 legacy TimerTask 类型，tsc 会报错但 vite build 不编译它们（未被引用）。不需要修复。
- SVG 层必须使用 `w-full h-full` 而不是 `width:0 height:0`，否则贝塞尔曲线不可见
